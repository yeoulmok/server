## 데이터 API

모두 같은 키 하나로 여러 API를 호출한다 (기관별 키 1개).

| 기관 | 용도 | 엔드포인트 | 응답 형식 |
|---|---|---|---|
| 한강홍수통제소 | 수위·강수량·관측소 제원 | `http://api.hrfco.go.kr/{HRFCO_KEY}/waterlevel/info.json` 등 | JSON |
| 기상청 API허브 | 관측 강수 (1분 단위, `RN_1HR` 포함) | `https://apihub.kma.go.kr/api/typ01/cgi-bin/url/nph-flood_sfc_sts_pkg` | 텍스트 / `disp=1`이면 CSV |
| 기상청 API허브 | 수치모델 강수 예보 | `https://apihub.kma.go.kr/api/typ01/cgi-bin/url/nph_flood_nwp_txt` | `\|` 구분 표 |

### 호출 예시 (키는 환경변수)

```
set -a; source ~/secrets/yeoulmok.env; set +a

curl -s "http://api.hrfco.go.kr/$HRFCO_KEY/waterlevel/info.json"
curl -s "https://apihub.kma.go.kr/api/typ01/cgi-bin/url/nph-flood_sfc_sts_pkg?stn=114&disp=1&authKey=$KMA_KEY"
curl -s "https://apihub.kma.go.kr/api/typ01/cgi-bin/url/nph_flood_nwp_txt?nwp=KIMG&varn=APCP&tm=202610290000&tmef1=202610290000&tmef2=202610290600&int=3&lat=37.34&lon=127.95&authKey=$KMA_KEY"
```

### 확인한 사실

- 한강홍수통제소 관측소 제원에 4단계 수위가 들어 있음: `attwl`(관심) / `wrnwl`(주의보) / `almwl`(경보) / `srswl`(심각). 위경도는 `128-33-04` 같은 도·분·초 문자열
- 기상청 관측: `RN_1HR`(1시간 누적)을 기상청이 직접 계산해 준다 → 우리가 더할 필요 없음
- 기상청 관측: 요청 시각 대비 **약 4분 지연** → 수집 시 "현재 − 5분" 기준
- 기상청 결측값: **`-99.9`** → 0으로 처리하지 말고 "자료 없음"
- 기상청 수치모델: `tm`·`tmef` 는 **UTC**, 6시간 간격
- 과거 구간 조회(`tm1`~`tm2`)가 0시부터 요청해도 12:00부터 나온 적 있음 → 한 번에 받는 줄 수 제한 여부 확인 필요
- 원주 관측소(114) 2025-07-19 정오 기준 12시간 누적 49.9mm (판부면 사고일). 시내 관측소 값이라 계곡 상류 값은 아님

### 보류

- 기상청 「레이더 추정강수량 데이터 지점 조회」: 검색에는 나오지만 신청 페이지(산업특화 > 수자원 > 홍수)에 없음
- 산림청 산악기상: 대상 계곡 근처에 관측소가 부족할 때 공공데이터포털에서 신청

## 키 관리 규칙

- 진짜 키는 VM `~/secrets/yeoulmok.env` 에만. 저장소에는 `.env.example`(이름만)
- 값만 넣는다. URL을 통째로 붙이면 `&` 때문에 bash가 줄을 쪼개 값이 비게 됨 (실제로 겪음)
- 터미널 로그를 공유할 때 키가 찍힌 줄은 지운다
- 약관상 키 공유 금지 → 이서연은 우리 서버 API를 통해 데이터를 받는다
